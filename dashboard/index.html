An empirical study of existing open-source projects · CMPT 479 · Simon Xie, Sukhdip Kandola, Thang To

Is TypeScript written by AI coding agents better or worse than code written by people?

We ran the same automatic quality checks on — real open-source projects. The short answer: the AI-built code is much tidier, with about —× fewer lint problems, but its functions are more tangled. On testing, there are too few projects to tell the groups apart.

Written by people— projects, each frozen at its last commit before 2021, before AI coding assistants existed, so no AI could have written them.

Built by AI coding agents— projects created in 2025 or later where most commits are signed by an agent such as Claude Code, Cursor or Codex.

How the comparison works

Pick fair pairs

GitHub search found — candidates; — passed screening. We kept — AI projects, each paired with a human one of similar size.

Freeze the code

Every project is checked at one fixed commit, so anyone can repeat the measurement and get the same result.

Run identical checks

The same seven automatic checks in the same Docker container: lint rules, copy-paste, install, compile, run the tests, and plant bugs to see if the tests catch them.

Ask: real or chance?

We compare the typical (median) project of each group and test whether a gap is too large to be luck with this few projects per side.

Definitions and method details
Typical project
The median: half the projects in the group score higher, half lower. Used instead of the average so one extreme project can't skew the result.
Lint problems
ESLint 9 with typescript-eslint and SonarJS rules, the same configuration for every project, ignoring the project's own settings and any "disable" comments.
Paths per function
Cyclomatic complexity (McCabe): the number of independent paths through a function. Above 10 is commonly treated as hard to test.
Planted bugs caught
Mutation score from StrykerJS 10: killed mutants over all valid mutants, on a seeded sample of about 400 lines per project.
Clear difference
Mann–Whitney U test, corrected for testing all the measures at once (Holm). "Clear" means the corrected p-value is below 0.05: a gap this large would rarely appear by luck.
Bar length
Cliff's δ: the chance a random project from one group beats a random project from the other, minus the reverse. Above 0.47 counts as a large effect.
Left out
H06 from mutation testing (its tests run compiled output), and mutation runs where more than half the planted bugs timed out.
